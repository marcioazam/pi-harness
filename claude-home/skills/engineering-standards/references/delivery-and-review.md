# Delivery and review

Review the actual diff against the request, contract, tests, security boundaries, and dependency changes. For substantial work, prefer a reviewer who did not author the change when an authorized independent context is available.

Keep commits focused and preserve unrelated work. Commit only when requested. A push or PR may be opened only for the active, named branch as an explicit delivery step; repository rules can be stricter. Never merge, publish, release, deploy, restart production services, rotate secrets, or rewrite history without an explicit current request.

Report completed actions, evidence, remaining risks, and blockers. Do not present a review as complete when its relevant checks did not run.
