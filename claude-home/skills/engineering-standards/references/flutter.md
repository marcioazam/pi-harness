# Flutter and Dart

Keep widget trees composable and state ownership explicit. Use immutable state, avoid expensive work in `build`, respect lifecycle and cancellation, and keep platform-channel boundaries typed and failure-aware. Test user-visible behavior with widget or integration tests; use golden tests only when visual stability is a real requirement.

Preserve accessibility labels, text scaling, localization, keyboard navigation, and responsive layouts across phone, tablet, web, and desktop targets that the project supports.

Current specifics (Flutter and Dart docs read 2026-10-24):

- Model loading, empty, error and success states without impossible combinations, and follow the project's state-management solution instead of adding one. Keep I/O out of `build`; narrow rebuilds only with evidence.
- Dispose controllers, cancel subscriptions, check `mounted` across awaits, and keep stable keys where list identity carries state.
- Run Flutter and Dart through the repository's pin when they are not on PATH (`mise exec -- flutter ...` with `.mise.toml`, `fvm flutter ...` with `.fvmrc`). Validate focus, semantics, text scaling and lifecycle with that tooling, on current APIs: `TextScaler`, not `textScaleFactor`; `isSemantics`, not `containsSemantics` ([breaking changes](https://docs.flutter.dev/release/breaking-changes)).
- Localized messages are generated into source since 3.32: import them from the configured output path, never `package:flutter_gen`. Keep messages complete, formatting locale-aware and fallbacks deliberate, and check text expansion in the supported locales.
- Keep the design-library import family the project uses (`package:flutter/material.dart` or the opt-in [`package:material_ui`/`cupertino_ui`](https://docs.flutter.dev/release/breaking-changes/material-ui-and-cupertino-ui), published with 3.47; the in-framework libraries are frozen since 3.44 and deprecated in 3.50, read 2026-11-11); migrate with `dart fix --apply --code=migrate_design_widgets` only when assigned, and report the frozen in-framework import as upgrade debt.
- iOS: [UIScene](https://docs.flutter.dev/release/breaking-changes/uiscenedelegate) is the default since 3.41 and Xcode 27 requires it, so create method channels and platform views in `didInitializeImplicitFlutterEngine`, and a custom `SceneDelegate` subclasses `FlutterSceneDelegate`; native dependencies use [Swift Package Manager](https://docs.flutter.dev/packages-and-plugins/swift-package-manager/for-app-developers), adding no CocoaPods step unless the repository already uses one. Android: with `android.builtInKotlin=true`, never apply `kotlin-android` ([built-in Kotlin](https://docs.flutter.dev/release/breaking-changes/migrate-to-built-in-kotlin)).
- pi has no Dart MCP server configured (`~/.pi/agent/mcp.json`) and no dart-and-flutter plugin skills: run `dart analyze`, `flutter analyze` and `flutter test` through `bash` with the repository's pin. If a Dart MCP server is added later, find its tools with `tool_search` first, use `analyze_files` for diagnostics and `run_tests` only if it is listed (off by default, per [dart_mcp_server](https://pub.dev/packages/dart_mcp_server)); repository instructions win.
