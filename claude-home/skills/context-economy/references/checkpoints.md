# Context and checkpoint boundaries

Use progressive disclosure: retain invariant instructions, select one relevant workflow, and load its supporting references only when needed. Do not load the whole skill catalog, all agent prompts, or every MCP schema speculatively.

Before a supported native compaction or handoff, update the existing task artifact with:

- Goal, authorized scope, owner, and current step.
- Owned files and current content identity, including relevant dirty changes.
- Decisions and assumptions with source and uncertainty.
- Executed checks with outcomes; remaining required checks and blockers.
- Next concrete action, remaining shared budget when measured, and stop conditions.

At a phase boundary choose in this order: continue when the next phase needs this conversation as a primary source; clear when nothing in it matters for what follows; hand off only when work moves to another harness, directory or person; delegate a bounded task that runs without the user; compact last, naming what to preserve. A handoff names the skills the next session should load and points to specs, ADRs, commits and diffs by path or URL instead of restating them. Adapted 2026-10-03 from Matt Pocock [phase boundaries](https://github.com/mattpocock/skills/blob/d81f3a183412e71a5b1e84ca21bc1a35eea03a60/skills/engineering/ask-matt/PHASE-BOUNDARIES.md) and [handoff](https://github.com/mattpocock/skills/blob/d81f3a183412e71a5b1e84ca21bc1a35eea03a60/skills/productivity/handoff/SKILL.md), MIT.

Prefer a natural phase boundary after exploration or a completed milestone. Do not compact merely because an arbitrary tool-call count was reached, and do not lose active failure evidence midway through diagnosis or implementation.

Every compaction restarts at the fixed prefix plus the summary and the kept recent messages (`compaction.keepRecentTokens`, default 20k), and every later turn re-sends that restart (pi measurement 2026-11-12: first request after compaction 67-89K; Claude Code 2026-11-09: ~125K). Most of the restart is rewritten at the cache-write rate, not read. `python3 ~/.pi/agent/claude-home/skills/context-economy/scripts/compaction_restart.py --since YYYY-MM-DD` reads the pi sessions (`~/.pi/agent/sessions/*/*.jsonl`) and reports the restart size and its share of main-thread prompt traffic. A high share is expected near the cost-optimal window. pi compacts when `contextTokens > contextWindow - reserveTokens`; here the threshold is 250k tokens on every model (cost model in `docs/pi-claude-harness-transfer-2026-11-12.md`, step 3) (`compaction.modelOverrides` in `~/.pi/agent/settings.json`, regenerated by `python3 ~/.pi/agent/scripts/compaction-400k.py` after `pi update` or new models; `~/.pi/agent/extensions/compact-at-400k.ts`, a historical name, covers models missing from the overrides; `PI_COMPACT_AT`, exported by the wrapper, changes both). The Claude Code window decision and its cost model remain in `~/.claude/docs/context-compaction-2026-11-08.md` as background.

After resumption, reread that artifact and applicable instructions, inspect current file state, and invalidate checks whose inputs changed. A checkpoint neither renews authorization nor authenticates an earlier test run.

Use pi's native context controls when they fit: `/compact [what to preserve]` (manual compaction with focus instructions), `/context` (usage), `/tree` or `/fork` (branch instead of compacting), and the `todo` tool. If the interface lacks one of them, report the limitation and use the existing durable artifact; never invent a successful tool invocation.

Avoid raw transcript ingestion, duplicate plans, automated memory writes, and background observers. Preserve exact diffs and security evidence when their wording matters. Unknown context/token usage is unknown, not zero.

Evaluate compression by total task cost and successful continuation, including refetches and rework after resumption. Fewer tokens in one request can cost more over the task. Preserve exact artifact identifiers in the existing checkpoint and verify current file state on return; do not add a competing artifact ledger merely to improve compression.

Task-cost guidance adapted 2026-09-20 from [context-compression](https://github.com/muratcankoylan/Agent-Skills-for-Context-Engineering/blob/6dbe1a1d868eab51a3bc9011b0f55e2891513e40/skills/context-compression/SKILL.md), [MIT](https://github.com/muratcankoylan/Agent-Skills-for-Context-Engineering/blob/6dbe1a1d868eab51a3bc9011b0f55e2891513e40/LICENSE). No fixed compression ratio or model-independent attention threshold is adopted.

ECC concepts: `strategic-compact` and `context-budget`, adapted locally without upstream hooks.
